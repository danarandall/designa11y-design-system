# Publication boundaries

Public: original Specs, machine-readable contracts, reusable guidance, sanitized findings, adaptation examples and rights-cleared exports.

Private: licensed reference material, shared designer-skill source locations without redistribution rights, internal notes, site deployment configuration, credentials and raw evidence requiring review.

Repository privacy applies to the entire repository, including history. A private-named subfolder in a public repository is public. Keep private resources in a separate private repository; do not add private remotes, source links or inaccessible dependencies to public agent entry points. Do not merge private working branches/history into the public repository. Publish reviewed snapshots or changes only.

The initial public snapshot excludes private source inventories, licensed-reference links and site deployment sources. Original working history is retained privately. Specs are published as Markdown for access without Figma permissions. Working Figma links record provenance; Community publication and duplication remain a separate release step.
